## 1. Kontrak sebelum implementasi

PRD §15/keputusan dimensi §15.2, schema B.6, backend/security dan NEXT M5 mengatur checkpoint ini. Owner command/data adalah Inventory. Hanya update factor internal: tanpa pair mutation, inverse/path otomatis, histori stok/ledger, lifecycle/status/archive/delete, endpoint/JSX/manifest/aktivasi atau migrasi development/deploy.

- Body strict hanya `factor` wajib, string desimal positif exact dalam batas 18 digit bulat/12 pecahan A/B1. UUID conversion target dari adapter, bukan body. Normalisasi trailing zero tanpa float/pembulatan memakai helper domain yang sama dengan create conversion; UUID target lowercase. Tidak menerima dimensi/precision/unit IDs/actor/scope/audit/quantity hasil atau expectedVersion baru dari klien.
- Fresh authorizer existing `inventory.master.manage` + all-outlet/Backoffice/no-device, membership/subscription/installation ACTIVE/capability sebelum validasi/IO, termasuk replay. Missing/foreign target satu 404 `INVENTORY_CONVERSION_NOT_FOUND`, tanpa detail workspace/parent. Legacy unknown atau dimensi berbeda ditolak `INVENTORY_UNIT_DIMENSIONS_INCOMPATIBLE` (409), **juga untuk no-op**, bukan di-remediate lewat perubahan factor.
- Setelah claim key Core, baca binding target scoped. Binding/identity immutable dan retention DB existing mencegah target berpindah/hilang; baca awal ini bukan before snapshot factor untuk audit. Lock kedua parent tenant-scoped dalam urutan UUID, lalu lock conversion row tenant-scoped `FOR NO KEY UPDATE` dan cocokkan binding. Urutan parent-before-conversion konsisten dengan create/reverse pair pada writer aplikasi; predicate dimensi sama/diketahui dijalankan atas parent stabil. Before factor harus dibaca dari row terkunci terkini, bukan lookup awal/client input. Writer SQL eksternal tetap tunduk pada guard DB dan rollback/retry PostgreSQL saat contention/deadlock; tidak mengklaim semua urutan arbitrary SQL bebas deadlock.
- Update hanya factor pada target; pasangan asal/tujuan/ID/tenant dan definisi parent tidak boleh diubah. Constraint numeric/compatibility/pair immutability/latch/retention B1/B2b2 tetap berlaku; tanpa schema/migration baru. Factor baru berlaku untuk pemakaian mendatang, bukan menghitung ulang hasil lama atau reciprocal. Precision unit bukan alasan membulatkan atau menolak factor kecil: quantity konkret nanti tetap exact-or-reject memakai primitive bigint.
- Row + audit kritis `inventory.unit_conversion.update` + key/hasil asli satu commit/rollback. Audit hanya pair IDs dan before/after factor string kanonik, actor/channel/request/correlation server. No-op (factor kanonik sama) tidak menulis row/timestamp/audit tetapi tetap menyimpan key/snapshot hasil, agar retry setelah update lain tidak mengaplikasikan ulang factor lama.
- Hash logical command mencakup target UUID + normalized factor, scoped tenant/actor/operation. Replay strict DTO `id/fromUnitId/toUnitId/factor`, target dan normalized input factor harus cocok; ID/binding/parent compatible dalam tenant diperiksa **di luar parser** pada transaksi sama. Replay mengembalikan hasil asli walau factor kini sudah berubah. Snapshot create dan update sebelumnya tidak direwrite; result dari operation/actor/tenant lain tidak dapat dipakai.
- Window 24 jam dan fail-closed Core existing: PENDING/FAILED/expired/incomplete/corrupt tetap reserved, tidak dihapus/dieksekusi ulang; tidak menumpuk interceptor HTTP generik. Fault audit/result/completion membatalkan mutation/timestamp/audit/key bersama. Tidak menambah event master atau LimitGate unit/conversion yang tidak ada di kontrak paket.
- Histori yang bisa dibuktikan pada checkpoint ini adalah original snapshots/audit master, bukan movement ledger yang belum dibangun. Tidak mengklaim rekonsiliasi atau migrasi stok historis; requirement ledger berikutnya tetap menyimpan base quantities/factor snapshot pada aksi operasional terkait.

## 4. Bukti dan batas

- **3 contracts + 8 source tests baru**: strict single factor wajib/exact, binding/metadata/derived fields ditolak; normalizer bersama create/update mempertahankan tiny/max/unsafe-integer digits tanpa float; enam use-case tests auth-first/normalization/target/key/origin/stable 404/409/infrastructure/privacy; critical audit dan label id/en. Create/read contracts tidak berubah. Helper fixture create hanya diekspor authorizer-nya dan wait-for-lock dipersempit opsional ke PID waiter tertentu untuk verifikasi barrier.
- **18 PostgreSQL tests baru (dua induk + 16 subtest)**: narrow DTO, pair/identity/tenant/created_at dan parent row tetap, attributed critical audit/status-200 snapshot; kelima dimensi pada precision 0 menerima factor minimum 10^-12, maksimum 18+12 digit dan angka melampaui safe integer tanpa pembulatan. Missing/foreign target satu 404 aman tanpa row/audit/key/foreign mutation.
- No-op kanonik tidak mengubah row/timestamp/audit, tetapi result/key tetap reserved dan tidak reapply sesudah perubahan lain. Delapan same-key attempts menghasilkan satu audit/mutation; UUID case, factor trailing zero dan key trim me-replay hasil asli walau factor terkini berubah. Snapshot create dan audit sebelumnya tidak direwrite. Tenant/actor/create-vs-update operation serta beda target/body satu key terisolasi.
- Fresh permission/all-outlet/device/capability/install/subscription/membership refusal berlaku juga sebelum replay tanpa mengubah key. PENDING/FAILED/expired/incomplete/wrong status/noncanonical/mismatched factor/ID/binding/metadata snapshot fail closed tanpa reapply. Fault injection audit/result/completion membatalkan factor/timestamp/audit/key bersama lalu retry sukses sesudah rollback/fault dilepas.
- Concurrent different-key updates menghasilkan audit chain before/after yang berurutan dari actual locked row. Reverse-pair updates dan duplicate create bersamaan selesai tanpa deadlock pada jalur aplikasi, duplicate tetap pair conflict. Writer yang menunggu external committed factor membaca before terkini setelah lock, termasuk no-op ketika factor baru sudah sama. Advisory barrier pada audit membuktikan parent editor dan conversion reader (PID waiter spesifik) menunggu hingga commit.
- Legacy unknown dan pasangan diketahui tetapi beda dimensi disisipkan pada history disposable sebelum guard terkait, lalu update maupun no-op ditolak tanpa rewrite unit/conversion/audit/key. Tidak ada movement ledger atau hasil quantity historis yang dipalsukan untuk test; bukti histori dibatasi pada snapshot/audit master yang memang tersedia.
