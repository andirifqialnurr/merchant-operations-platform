Lokasi fakta: konteks bisnis/outlet hanya di shell; atribut outlet milik resource bukan pengulangan konteks. P2/P3 tabel tersembunyi di bawah 768px harus dapat dibaca di detail, tidak hilang; hanya tampil di detail pada breakpoint itu. Status tetap satu badge di daftar. Tidak membuat fakta menjadi editable, menambah kartu, atau mengubah daftar field produk.

## Temuan baseline

- `.cache/m2-visual-baseline`: 20 screenshot, 1440 light id dan 320 dark en. Form Bisnis dan susunan Langganan sudah memiliki jarak bagian yang jelas. Daftar dengan data pendek terlihat baik, tetapi itu belum menguji baris multiline; tidak perlu merombak halaman hanya demi perubahan.
- Integrasi: tiga binding nyata menjadi tiga baris, tetapi dua hubungan dapur terlihat identik (`CORE_ORDER → Layar dapur`), padahal event berbeda. `CORE_BILL` dan `CORE_ORDER` adalah kode internal, bukan label merchant. Keterangan Aktif mengulang sumber/tujuan yang sudah tampil di baris.
- Source audit: kolom sekunder anggota/undangan dan perangkat disembunyikan pada Small, tetapi belum dipindahkan ke detail. Koreksi harus memberi lokasi alternatif tanpa menggandakan fakta di Large.

## Bukti dan batas verifikasi

- Runner visual lokal hanya membaca data dan membuka form; tidak submit, mengubah preferensi/PIN, membuat atau menerima undangan, membuat/mencabut perangkat, atau menjalankan retry nyata. Skenario tambahan memalsukan respons baca di browser, **bukan** fakta langganan/status produksi. Guard test menolak write API yang tidak dimock.
- Matriks representatif: 320 dark en, 390 light id, 767 light en, 768 dark id, 1279 dark en, 1280 light en, 1440 light id, 1440 dark en. Bukan semua kombinasi browser/perangkat. Form/detail, matriks sebelum/sesudah scroll, menu preferensi dan PIN ikut dicapture.
- Stress mencakup email/nama panjang, undangan pending/expired/revoked, lima state Integrasi + disabled yang tidak dirender, state kosong/aktif saja, retry hanya untuk kegagalan dan izin kelola, detail perangkat read-only, empat state usage, langganan kosong, aktivasi, serta terima undangan untuk akun baru/lama. Respons permission read-only hanya proyeksi browser; bukan pengganti pengujian authorization server.
- Assertion memeriksa padding baris, batas field/Sheet/tabel, satu badge terlihat, teks internal tidak bocor, field kondisional, dan menu akun sudah menutup. Pemeriksaan overflow halaman saja sebelumnya melewatkan tabel yang terpotong di dalam wrapper; sekarang overflow internal tabel juga diuji.
- Screenshot sampel benar-benar dibaca: semua area utama, form brand/outlet, form undangan/perangkat/peran, matriks desktop/HP, detail Small, PIN, integrasi campuran desktop/HP, email panjang, usage dan terima undangan. Tidak mengklaim semua hasil capture ditinjau satu per satu.
- Pada satu run campuran, `/auth/session` lokal sempat merespons 500 dan satu kombinasi berhenti pada error state. Trace menunjukkan kegagalan sesi, bukan layout. Suite diulang tanpa pengujian database bersamaan; tidak menambahkan retry yang menutupi error atau mengklaim akar 500 sudah diperbaiki.
- Gate akhir: **12 browser test lulus (4,3 menit), 232 screenshot** di `.cache/m2-verified` (Git-ignored): 168 capture dari delapan kombinasi umum + 64 capture state/stress/read-only. Log lokal: `/tmp/m2-verified.log`. Hasil ini tidak berarti setiap screenshot disetujui manusia.
- Regresi KDS diulang setelah koreksi primitive bersama: **4 passed (1,8 menit)**; web/API test 4100/4101 dan database disposable, bukan development 4000/4001. Root lint/boundary/warna, typecheck, unit/component test (termasuk 280 test UI), format lulus. Web lint/typecheck diulang untuk perubahan read-only terakhir; build produksi web terisolasi `.next/m2-build` juga diulang dan lulus. File generated `next-env.d.ts` dikembalikan ke jalur development; tidak termasuk perubahan checkpoint.

Hasil ini menutup pekerjaan koreksi teknis, **bukan** persetujuan visual pengguna yang baru. Review pengguna KDS/M2 dan uji monitor/suara dapur fisik tetap terbuka. Tidak memulai M4/M5.
