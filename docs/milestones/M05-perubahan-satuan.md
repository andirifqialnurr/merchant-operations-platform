## 1. Kontrak sebelum implementasi

PRD §15, keputusan dimensi §15.2, schema B.6, backend/security dan NEXT M5 mengatur checkpoint ini. Owner data/use case adalah Inventory. Hanya update unit internal; tanpa update factor conversion, status/archive/delete, klasifikasi dimensi legacy, endpoint/JSX/manifest/aktivasi/ledger atau migrasi development/deploy.

- Patch strict hanya `code/name/precision`, minimal satu nilai terdefinisi. Code/name trim dan batas A, precision integer 0–6. UUID target adalah identitas resource dari adapter, bukan field body; scope/aktor/permission/key/origin dari konteks server. Dimensi tidak bisa diedit, termasuk NULL legacy atau nilai yang sama; tidak menyisipkan lifecycle yang belum ada.
- Fresh authorizer existing `inventory.master.manage` + all-outlet/Backoffice/no-device, membership/subscription/installation ACTIVE/capability, sebelum validasi/IO dan sebelum setiap replay. Missing/foreign UUID target satu 404 `INVENTORY_UNIT_NOT_FOUND`, tanpa detail tenant.
- Writer claim key Core lalu lock target `FOR NO KEY UPDATE` tenant-scoped dalam transaksi. Domain memeriksa actual before snapshot: nama boleh diperbaiki; code/precision hanya boleh berubah bila `definition_locked = false`. Nilai code/precision identik bukan perubahan walau field disertakan pada patch. Perubahan casing code tetap perubahan definisi. Guard SQL B1 tetap melindungi writer lain/race referensi pertama; jangan me-reset latch atau menafsirkan ulang stok/referensi lama.
- Patch parsial diterapkan ke row terkunci terkini, bukan full replacement stale client; update berurutan berbeda key adalah last-writer untuk field yang sama, tanpa menimpa field yang tidak dikirim. Tidak menambah expectedVersion/timestamp input tanpa kontrak. CI code conflict `INVENTORY_UNIT_CODE_TAKEN` (409); definisi terpakai `INVENTORY_UNIT_DEFINITION_LOCKED` (409). Tidak menambahkan kuota unit, event master atau LimitGate yang tidak dikontrak produk.
- Mutation + audit kritis `inventory.unit.update` + key/snapshot hasil satu commit/rollback. Audit before/after hanya code/precision, flag `nameChanged` (tanpa teks nama bebas), aktor/channel/request/correlation dari adapter tervalidasi. No-op (patch nilai sama) tidak mengubah updated_at atau menambah audit mutasi; tetap menyimpan key/hasil original secara atomik agar retry sesudah perubahan lain tidak mengaplikasikan ulang patch lama.
- Hash logical command mencakup UUID target lowercase dan patch ternormalisasi, dengan key scoped operation/actor/tenant. Snapshot hasil `id/code/name/precision/dimension` yang asli divalidasi strict, target dan semua field patch harus sesuai; keberadaan target dalam tenant dan dimensi immutable diperiksa di luar parser di transaksi yang sama. Replay bukan read nilai master terkini atau eksekusi ulang guard definisi terhadap patch lama. Dengan demikian update sukses sebelum reference pertama tetap dapat direplay sesudah unit direferensikan, tanpa mengubah definisinya lagi.
- Window Core 24 jam; same key beda target/body ditolak, actor/tenant/operation terpisah. PENDING/FAILED/expired/incomplete/corrupt tetap fail closed/reserved, tidak dihapus/dijalankan ulang. Snapshot create B2b1 dan hasil operasi lain tidak direwrite oleh update; interceptor HTTP generik tidak ditumpuk nanti.
- Tidak ada migrasi atau perubahan constraint/schema DB pada checkpoint ini: existing CI uniqueness, immutable identity/dimension, latch dan retention tetap sumber guard SQL. Legacy dimensi NULL tetap NULL tanpa tebakan. Kegagalan audit/result/completion membatalkan row/timestamp/audit/key bersama; retry setelah rollback tidak mewarisi reservation parsial.

## 4. Bukti dan batas

- **3 contracts + 10 source tests baru**: patch strict/partial/nonempty, optional undefined bukan reset, metadata/immutable dimension/status ditolak; domain unused/locked/no-op dan pure input; enam use-case tests auth-first/normalization/UUID/key/origin/404/409/infrastructure/privacy/legacy NULL; audit critical + id/en coverage. Tidak ada perubahan contract create/read atau metadata hasil yang dibocorkan.
- **18 PostgreSQL tests baru (dua induk + 16 subtest)**: row scoped, partial patch tidak menimpa omitted fields, legacy dimensi NULL tetap unknown, item/conversion references, allowed rename vs blocked definition/case change, CI duplicate/race, delapan same-key updates menghasilkan satu audit/hasil. Audit before/after/code/precision/nameChanged, actor/channel/request/correlation, status 200 dan nonsecret original snapshot/key diverifikasi.
- No-op tidak menulis row/timestamp/audit, tetapi menyimpan hasil/key dan tidak mengaplikasikan ulang patch setelah perubahan berikutnya. Concurrent different-key disjoint patches mempertahankan kedua perubahan. Normalized target UUID, trim/key/JSON field order me-replay hasil asli sesudah update lain dan reference pertama; snapshot create B2b1 tetap dapat direplay tanpa rewrite. Key berbeda actor/tenant/operation dan target/body mismatch diuji dengan dua workspace/owner kedua/create unit sungguhan.
- Fresh permission/all-outlet/device/capability/install/subscription/membership refusal berlaku juga sebelum replay dan tidak mengubah key. PENDING/FAILED/expired/wrong status/incomplete/mismatched target/patch/dimension/metadata snapshot fail closed tanpa reapply. Fault injection audit/result/completion membatalkan row/timestamp/audit/key bersama, lalu key dapat dipakai lagi sesudah rollback/fault dilepas.
- Race nyata: item atau conversion reference memegang row lock terlebih dulu, update menunggu lalu ditolak definisi terkunci. Urutan sebaliknya ditahan advisory barrier pada audit: referensi item menunggu commit update lalu mengecek precision baru, menolak minimum pecahan tak sesuai atau menerima nilai integer dan melatch. Tidak ada stale before snapshot/interpretasi ulang stok.
