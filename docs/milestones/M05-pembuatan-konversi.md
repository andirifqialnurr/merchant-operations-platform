## 1. Kontrak sebelum implementasi

PRD §15 (termasuk keputusan dimensi di §15.2), Module Tiers §7, Packages & Limits §4.6/§5.5, schema B.6 dan backend/security mengatur checkpoint ini. Owner tabel/command/read DTO adalah Inventory. Tidak menambah AppModule/manifest/HTTP/OpenAPI/UI/ledger/event, dependency Catalog/POS/KDS, deployment atau migrasi development.

- Command hanya `fromUnitId/toUnitId/factor` sesuai shared strict contract. Kedua UUID dinormalisasi lowercase dan factor positif ke string desimal kanonik tanpa float, eksponen atau pembulatan; hash logical body memakai bentuk normal ini. Definisi tidak menerima quantity hasil, dimensi, precision, scope/actor/audit/status dari klien. Response hanya `id/fromUnitId/toUnitId/factor`.
- Permission `inventory.master.manage`, all-outlet/Backoffice/no-device dan fresh membership/subscription/installation ACTIVE/capability `inventory.item.manage` memakai authorizer B2b1 yang sama, termasuk sebelum replay. Unit tidak memiliki lifecycle status; tidak mengada-adakan filter ACTIVE pada model tanpa status. Missing atau parent milik tenant lain dijawab `INVENTORY_UNIT_NOT_FOUND` tanpa mengungkap parent mana/tenant lain.
- Dalam transaksi: claim key operation+actor+tenant melalui helper Core existing; sebelum insert, lock kedua parent scoped dengan `FOR NO KEY UPDATE` dalam urutan UUID deterministik, pastikan dua parent ditemukan dan predicate dimensi sama/diketahui lulus. Lock menahan perubahan definisi/reference race sampai commit. Trigger DB juga memeriksa dimensi untuk INSERT/UPDATE conversion setelah lock yang sama, bukan hanya percaya writer. Unknown legacy dan MASS→VOLUME ditolak. Missing parent tetap dilindungi FK komposit.
- Satu pasangan **terarah** per tenant. Race key berbeda pada pasangan sama menjadi `INVENTORY_CONVERSION_PAIR_TAKEN`; dimensi incompatible menjadi `INVENTORY_UNIT_DIMENSIONS_INCOMPATIBLE` (409). Tidak membuat reciprocal/path atau menyimpulkan factor dari label/dimensi. Faktor harus eksplisit; dimensi sama tidak membuktikan nilai fisiknya benar.
- Factor exact mengikuti batas 18 digit bulat/12 pecahan A/B1. Definisi factor tidak harus mengubah setiap atom asal menjadi atom tujuan: jumlah konkret nanti tetap lewat primitive bigint dan ditolak bila inexact/overflow. Tidak memalsukan quantity uji 1 atau menolak factor kecil yang valid hanya karena target precision; tidak ada mutasi stok pada create.
- Conversion + latch parent + critical audit `inventory.unit_conversion.create` + completed key/snapshot hasil satu commit/rollback. Audit aman hanya pasangan/factor (tanpa nama bebas/body/key/hash); actor/channel/request/correlation dari adapter tervalidasi. Tidak menambahkan event master yang belum dikontrak produk atau LimitGate unit/conversion yang tidak ada di paket.
- Replay memakai hasil **asli**, bukan factor terkini setelah koreksi mendatang. Validate strict DTO, kesesuaian normalized input, ID/pasangan milik tenant dan kedua parent kompatibel. DB checks di luar parser hasil agar gangguan infrastruktur tidak dilabeli corrupt DTO. Key berbeda actor/tenant/operation tidak bisa mengambil snapshot pihak lain. Window 24 jam; PENDING/FAILED/expired/incomplete/corrupt tetap fail closed, tidak dihapus/dieksekusi ulang; tidak menumpuk interceptor HTTP generik.
- Migrasi hanya mengganti fungsi guard conversion; tidak backfill/mengubah conversion legacy, factor, unit, audit atau key. Legacy unknown/incompatible tetap bisa dibaca sebagai histori, bukan dinyatakan valid untuk stok; perubahan row conversion tersebut ditolak guard sampai remediation tersendiri. Tidak ada API update/klasifikasi legacy di sini. Rollback jangan menghapus guard/data untuk meloloskan konversi; hentikan writer dan gunakan koreksi maju melalui proses rilis yang disetujui. Kode writer baru wajib dipakai bersama migrasi rilis terkait.

## 4. Bukti dan batas

- **10 source tests baru**: normalization factor exact/UUID case/idempotence tanpa float, enam use-case tests (auth-first, strict input, key/origin, stable 404/409 vs infrastructure, DTO privacy), tiga schema/guard/error-label tests. Audit critical classification existing diperbarui. Shared create/read conversion contract tidak berubah; tidak menambah request field/dimensi buatan.
- **19 PostgreSQL tests baru (dua induk + 17 subtest)**: current writer dan guard/upgrade fixture terpisah, hanya database disposable milik invocation. Existing legacy conversion unknown tetap persis sama sebelum/sesudah migrasi dan masih dapat dibaca, tetapi perubahan row ditolak guard. Unit unknown/known atau beda dimensi ditolak di writer maupun raw SQL; FK komposit/missing parent tetap terjaga. Kelima dimensi dengan precision 0 diuji untuk minimum factor 10^-12 dan maksimum 18+12 digit exact, bukan quantity/stock conversion.
- Audit/actor/channel/request/correlation, dua latch dan completed result diverifikasi. Delapan same-key attempts menghasilkan satu audit/ID; race different-key pada pasangan sama meninggalkan satu reservation sukses; reverse pairs eksplisit berbarengan selesai tanpa deadlock. Normalized UUID/case/trailing-zero/key dan JSON order me-replay snapshot create asli walau factor row sudah berubah. Tenant/actor/operation-key isolation memakai dua workspace, owner kedua dan key yang sama dengan create unit sungguhan.
- Fresh permission/scope/device/capability/installation/subscription/membership refusal berlaku juga untuk replay dan tidak mengubah key. Corrupt/uncertain/expired/incomplete/noncanonical/foreign/wrong-pair/missing-ID snapshot fail closed tanpa mutasi ulang. Fault injection audit, result factor dan completion membatalkan conversion, kedua latch, audit/key sekaligus; key yang rollback bisa dicoba lagi setelah fixture fault dilepas.
- Race nyata mengunci audit di advisory barrier lalu mencoba edit precision parent: editor menunggu writer dan ditolak definition latch sesudah commit. Race legacy classification vs create menunggu row lock, membaca dimensi committed baru lalu melatch tanpa stale assumption. Parent tetap workspace-scoped dan lock UUID deterministik.
