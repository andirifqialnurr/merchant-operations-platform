## 2. Atomisitas, limit dan replay

Fresh `inventory.master.manage`/all-outlet/no-device authorizer existing sebelum setiap validation/attempt/replay. Input/origin/key strict dan UUID/decimal canonical sebelum hash. Actor/operation/workspace scope Core helper, response 201/24h seperti command existing.

LimitGate perlu check dengan owner count dalam transaksi, bukan gauge global sebelum create. Tambahkan opt-in prepared counted check pada kontrak shared/Core metering: resolve policy existing sebelum transaksi (tidak memegang pool connection/row lock sambil meminta koneksi kedua), capture immutable finite/unlimited/absent allowance, lalu pure check exact bigint owner count di dalam transaksi. Tidak mengubah perilaku gate/gauges existing atau mempublish runtime gauge/modul Inventory. Policy snapshot fresh per attempt, bukan klaim atomic live package-downgrade dengan transaksi item. Replay tidak ditolak hanya karena quota kini penuh/lebih rendah.

Owner transaction: Core reservation → advisory xact lock workspace `inventory-items-active` → unit scoped row lock → optional category scoped row lock → actual ACTIVE count + prepared gate → insert ACTIVE → critical audit → strict original result/key completion. Advisory hash collision hanya over-serialize, tidak bypass; future item/status mutation wajib ikut quota/parent lock convention; baseUnitId item tetap immutable menurut guard B1, bukan workflow rebasing baru. Count excludes INACTIVE; raw SQL bukan public authorized command dan tidak dijanjikan mengikuti limit. No usage event/counter untuk HARD_COUNT; future runtime gauge harus membaca rows, bukan menambah event setiap create.

Audit initial status/baseUnitId/categoryId saja, tanpa free-text nama/SKU atau quantity finansial. Item/latch/audit/key/result rollback bersama pada parent/precision/quota/CI-SKU/audit/completion/result failure. Key rollback boleh dicoba lagi setelah penyebab diatasi; uncertain/expired/corrupt persisted keys tidak dihapus/dijalankan ulang.

Replay memvalidasi DTO/input/original ACTIVE, item scoped existence dan original parent scoped existence, bukan mutable current name/status/category/minimum atau parent ACTIVE terkini. Tidak menulis ulang history/snapshot setelah rename/deactivation/reassignment. Parent retention/immutable unit precision melindungi definisi lama. Tidak membandingkan field mutable dengan row saat replay.
