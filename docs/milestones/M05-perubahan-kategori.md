## 1. Kontrak sebelum implementasi

PRD §15, schema B.6, backend/security dan NEXT M5 mengatur checkpoint ini. Owner command/data adalah Inventory. Hanya rename kategori internal; tanpa lifecycle/status change, item reattachment, hierarchy/delete, migration/grant baru, AppModule/manifest/HTTP/OpenAPI/JSX/ledger/aktivasi/deploy atau mutasi development.

- Body strict hanya `name` wajib, trim/min 1/max 160/case-preserving seperti create. UUID target dari adapter, bukan body. Status/identity/tenant/origin/audit/timestamp bukan field rename. Nama kategori ACTIVE maupun INACTIVE boleh dikoreksi; rename tidak mengaktifkan/nonaktifkan kategori atau mengganti relasi item/histori. Perubahan casing nama adalah perubahan nyata; trim ke nilai sama adalah no-op.
- Otorisasi fresh existing `inventory.master.manage` + all-outlet/Backoffice/no-device, membership/user/workspace aktif, subscription usable, instalasi ACTIVE (missing ditolak), capability `inventory.item.manage`; sebelum validasi/IO, juga pada replay. Izin baca operasional bukan hak mutation. Missing/foreign target satu 404 `INVENTORY_CATEGORY_NOT_FOUND`, tanpa detail tenant.
- Claim key Core lalu lock target tenant-scoped `FOR NO KEY UPDATE`. Before name/status berasal dari row terkunci terkini. Update hanya name memakai composite scoped key; status, id, tenant dan item FK tidak diubah. CI uniqueness B1 termasuk kategori INACTIVE: conflict menjadi `INVENTORY_CATEGORY_NAME_TAKEN` (409), tanpa overwrite/reactivation atau SQL detail. Tidak menambah expectedVersion/timestamp/slug/parent input, kuota kategori atau event master.
- Row + critical audit `inventory.category.update` + completed key/original result satu commit/rollback. Audit aman hanya flag `nameChanged: true` dengan actor/channel/request/correlation/entity server; tidak menduplikasi nama bebas sebelum/sesudah, body/key/hash. No-op tidak menulis row/timestamp/audit tetapi tetap menyimpan key/snapshot agar retry sesudah perubahan lain tidak reapply nama lama.
- Hash logical command mencakup UUID target lowercase dan normalized name, scope tenant/actor/operation. Same key beda target/name/casing berbeda ditolak; actor/tenant/create-vs-update terpisah. Concurrent different-key updates terserialisasi pada row: last-writer untuk name, tanpa menimpa status/field yang tidak dimiliki action. Existing create/replay snapshot dan audit sebelumnya tidak direwrite.
- Result DTO strict hanya `id/name/status`. Mutasi pertama memvalidasi hasil terhadap target/name baru **dan before status** supaya rename tidak menyelundupkan lifecycle change. Replay memvalidasi target/input name/status enum dan scoped existence di luar parser, **bukan** current name/status yang mutable; hasil pertama tetap dikembalikan walau kategori kemudian rename atau berubah status. Ini tidak mengklaim cryptographic integrity terhadap arbitrary database administrator tampering.
- Window Core 24 jam; PENDING/FAILED/expired/incomplete/corrupt tetap reserved/fail closed, tidak dihapus/dijalankan ulang. Fault audit/result/completion membatalkan row/timestamp/audit/key bersama. Jangan menumpuk interceptor HTTP generik nanti. Tidak ada migration/schema baru; CI scoped/immutable identity/retention guards B1 tetap berlaku.

## 4. Bukti dan batas

- **3 contracts + 7 source tests baru**: required name-only/trim/case-preserving/batas panjang, status/identity/relations/metadata ditolak; enam use-case tests auth-first/target/key/origin/404/409/infrastructure/narrow ACTIVE atau INACTIVE DTO. Critical audit/nameChanged flag dan label private error id/en diverifikasi. Create/read contracts tidak berubah; schema rename menggunakan validator name yang sama.
- **16 PostgreSQL tests baru (dua induk + 14 subtest)**: rename kategori ACTIVE/INACTIVE mempertahankan status/id/tenant/created_at dan item FK/minimum/metadata existing, narrow result/status-200 key serta attributed audit tanpa nama bebas. CI conflict termasuk nama kategori INACTIVE, different-target race satu nama dengan satu reservation sukses, own casing correction sah, delapan same-key attempts satu audit/result.
- No-op tidak menulis row/timestamp/audit tetapi tetap reserved; retry sesudah rename/status berubah tidak reapply nama/status lama. Normalized UUID/name/key retry mengembalikan original snapshot, create replay tetap asli dan query B2c1 membaca current state. Beda target/name/casing satu key ditolak; actor/workspace/create-vs-update key terisolasi dengan dua workspace/owner kedua.
- Fresh permission (operasional read bukan write), all-outlet/device/membership/user/subscription/module/install/capability denial sebelum replay tidak mengubah key. PENDING/FAILED/expired/incomplete/wrong response status/mismatched target/name/invalid status enum/leaked snapshot fail closed tanpa reapply. Mutability status sah saat replay bukan pembuktian cryptographic integrity terhadap arbitrary DB tampering.
- Fault injection audit, result name, result lifecycle status dan completion membatalkan row/name/status/timestamp/audit/key bersama; key dapat dipakai lagi setelah fault dilepas/rollback. Mutasi pertama membuktikan result status sama dengan before locked row, bukan mempercayai storage output untuk mengubah lifecycle.
- Different-key concurrent renames terserialisasi, menghasilkan dua successful original results/audits tanpa status overwrite. Writer yang menunggu perubahan status/name eksternal membaca committed row terkini, termasuk no-op. Advisory barrier pada critical audit membuktikan status editor dan reader (PID spesifik, termasuk blocking queue) menunggu commit; writer hasil awal tetap ACTIVE dan editor sesudahnya mengubah current status tanpa lost rename. Perubahan status di test hanya fixture SQL, bukan implementasi B2c3b.
